# 平板主人的安装与测试指南

适用版本：0.3.0｜更新日期：2026-10-22｜设备：安卓平板。

这台平板负责运行游戏和显示公共局面。你自己也可以拿手机参加游戏；平板操作不需要你知道其他人的身份。程序通过 Termux 启动，游戏界面在浏览器打开。

## 一、先准备这些

- 安卓平板，建议 Android 7 或更新版本，保留足够空间并准备充电器。
- 本次交付的 `blood-clocktower-android-ai.zip`。
- Termux，按 [官方安装说明](https://github.com/termux/termux-app#installation) 选择来源。
- 安装时需要互联网。聚会时若各用自己的网络，平板和每部手机都需要持续联网。
- 使用 AI 时需要 DeepSeek API Key。先不填密钥，也能测试纯自动情报模式。

## 二、第一次安装

1. 把压缩包保存到平板的“下载 / Download”文件夹。若已在文件管理器解压，可以先打开其中的 `先读我.html` 看说明；运行程序仍按下面步骤进行。
2. 安装并打开 Termux。逐行复制执行：

   ```sh
   pkg update
   pkg install nodejs-lts unzip nano
   termux-setup-storage
   ```

   出现文件访问权限提示时允许。安装软件包时若询问是否继续，输入 `y` 并回车。
3. 解压到 Termux 自己的目录：

   ```sh
   unzip ~/storage/downloads/blood-clocktower-android-ai.zip -d ~/
   cd ~/blood-clocktower
   sh start-android.sh
   ```

4. 看到“本机（平板）”地址和“房主 PIN”，表示服务已经启动。保持 Termux 运行，切换到浏览器，打开显示的本机地址。它类似 `http://127.0.0.1:3000/host?pin=四位数字`，PIN 以你屏幕上实际显示的为准。
5. 在系统设置中，允许 Termux 后台运行，把电池策略设为“不限制”或同等选项。聚会时让平板持续供电，避免清理后台。

程序没有第三方 npm 依赖，不需要执行 `npm install`，也不需要安装额外的游戏 APK。

## 三、先做一个小测试

先不要急着开正式局，按顺序确认：

| 检查 | 怎么做 | 通过标准 |
|---|---|---|
| 平板服务 | 浏览器打开 `http://127.0.0.1:3000/health` | 显示包含 `"ok":true` 的文字 |
| 公共屏 | 打开终端给出的本机房主地址 | 能看到大厅、人数与座位 |
| 手机入座 | 一部手机打开加入链接，输入名字并选座 | 平板能看到这部手机加入 |
| 后台运行 | 切到浏览器并等待几分钟 | Termux 没被系统停止，手机没有持续掉线 |

这一步只证明基本连接。七个人是否都能顺畅使用，需要后面的全员测试。

## 四、让大家各用流量或 Wi-Fi

你们计划使用这一种。平板可以连谁的热点，也可以连普通 Wi-Fi；其他人各自有网即可。

1. 回到 Termux，按 `Ctrl+C` 停止刚才的服务。Termux 可用底部扩展键的 CTRL 配合字母 C。
2. 第一次额外安装：

   ```sh
   pkg install cloudflared
   ```

3. 启动公网房间：

   ```sh
   cd ~/blood-clocktower
   sh start-android.sh --tunnel
   ```

4. 平板仍用“本机（平板）”地址。等待大厅出现类似 `https://某个名字.trycloudflare.com/player` 的加入链接，点“复制链接”或“分享链接”，只发给这桌朋友。
5. 找一部手机关闭 Wi-Fi、只用流量打开这个链接。如果能入座，再让其他人加入。

**手机不能使用 `127.0.0.1`，也不要分享带 `pin=` 的房主地址。** 平板重启隧道后公网地址会改变，要重新分享。临时隧道的网络可用性需要现场确认；打不开时先尝试更换平板网络。

备用方案：让大家连同一个 Wi-Fi 或热点，用平板的局域网地址加入。关闭 AI 的局域网模式在安装完成后不需要互联网。

## 五、配置和单独测试 DeepSeek

1. 停止服务，在 Termux 执行：

   ```sh
   cd ~/blood-clocktower
   cp ai.config.example.json ai.local.json
   nano ai.local.json
   ```

2. 只把 `apiKey` 后的空字符串填成你的密钥，其他内容可以保留。`enabled` 保持 `false`，方便每次手动启用。
3. 在 nano 中按 `Ctrl+O`、回车保存，`Ctrl+X` 退出。用原来的方式重启，例如 `sh start-android.sh --tunnel`。
4. 打开平板的“说书人操作”，点 **“测试连接（1 次调用）”**。这会向实际配置的服务发起一次请求，按服务商规则计费；测试不会发送对局身份，也不会开始游戏。
5. 看到“DeepSeek 连接测试成功”后，点“启用 AI”。如果失败，检查密钥、余额、模型名、接口地址和平板网络。

“已配置”只代表读取到了配置；“测试成功”才表示这次 API 请求完成。模型默认 `deepseek-flash`，详细配置见 [DeepSeek配置.md](../DeepSeek配置.md)。密钥只留在平板，不用发给玩家。

## 六、聚会前的全员测试

请在正式玩的地点，至少完整走一夜：

1. 平板和七部手机全部进入同一房间，每人固定一个座位。
2. 开始游戏，所有人都能按住查看自己的身份，并点“我知道了”。平板只显示确认人数。
3. 开始第一夜。被叫到的人完成选人或情报确认，其他人继续等待。检查自己能否读懂手机提示。
4. 确认夜间能自动走到天亮；不能只依靠连续“跳过”证明游戏正常。
5. 平板开始提名，一人提名另一人，大家投一次票。核对手机反馈和平板票数。
6. 让一部手机切后台再回来，检查是否恢复原座位；不要清浏览器数据。
7. 如开启 AI，观察有裁量空间的信息请求能否完成；失败时应自动发情报，不能把整桌卡住。固定答案不会调用模型。
8. 测试局结束后，点“重开一局”准备正式游戏，避免沿用测试身份。

目前代码和模拟联机已验证；你们的安卓平板、浏览器及运营商网络尚未真机确认。上面这次全员测试是交付验收的一部分。

## 七、每次开局与结束

平时只需要：联网 → Termux 运行启动脚本 → 平板打开公共屏 → 分享当前加入链接 → 等人齐 → 开始游戏。启用 AI 前可以先测一次连接。

白天的“开始提名”“结束提名”、进入下一夜仍由平板操作。全桌确认不用继续时，可点“提前结束”，输入“好人”或“坏人”并再次确认；会立即亮牌。

结束后回 Termux 按 `Ctrl+C`，对局保存在 `room.json`。再次启动会恢复；“重开一局”用于重新发牌。

## 八、升级、备份和常见问题

升级应在一局结束后，先停止服务、保留旧目录。可在 Termux 执行 `cp -a ~/blood-clocktower ~/blood-clocktower-backup-20261022`；后续换未使用过的备份名。尤其保留 `room.json` 与 `ai.local.json`，不要发群里。0.3.0 可读旧存档，但不能撤回旧版已发信息；升级后另开一局、先做小测试。最新运行包也可从私密 GitHub 仓库的 Releases 下载，需有权限的账号登录。

| 现象 | 先检查 |
|---|---|
| 手机打不开链接 | 是否用了当前公网 `/player` 链接，是否误用了本机或旧隧道地址 |
| 平板能开、手机不能开 | 隧道是否就绪；局域网模式下是否同网、有设备隔离 |
| 切到浏览器后全部掉线 | Termux 是否被省电或后台清理停止 |
| 无法自动识别平板 IP | 共同局域网时从 Wi-Fi 详情查看；公网模式等待隧道链接 |
| 提示端口被占用 | 是否已经有一个游戏服务在运行；先回原终端停止旧服务 |
| AI 失败但游戏继续 | 已回退，先继续对局；休息时检查配置和网络 |
| 手机丢失座位 | 先回原浏览器和原链接，不要立即清数据或重开 |

遇到问题，记录发生步骤、时间、手机和平板系统版本、错误提示即可。截图不要带身份卡、PIN 或 API Key。
